### Walras（插件脚本）
- 实现里被丢弃的方程是第 N 个（地区 R），其出清方程被计价单位替换，但 `market_clearing_residuals` 记录的是**全部三个**出清残差，所以 clearing_R = 7.0e-17 才是真正的被删方程残差，检验成立。
- 我在随机非均衡 ŵ 上验证：Σ 残差 ≡ 0（~1e-16），说明 Walras 在方程层面是恒等式。因此该检验能捕捉 (3)(4) 式的编码错误，但不能证明经济含义正确。
- 脚本里的 SAM 检验用 `rows = ŵY + R' + D'`、`cols = E'`，而 `E' = (ŵY + D')/(1 − ρ)`、`R' = ρE'`，代数上恒等，**同样没有检验力**。
- 残差按世界总产值（~1.0e5）归一化，容差 1e-9 对应绝对残差约 1e-4，从绝对量看偏松。实际值 1e-17，不构成问题。

### ACR 解析检验——不具实质意义
- 检验量：Ŵ_j = (λ̂_jj)^(−1/ε)。在单部门、D = 0、t = 0 时，由 Ŵ_j = E'/E/P̂、E' = ŵY 和 λ̂_jj = (ŵ_j/P̂_j)^(−ε)，这是一条对**任意 ŵ** 都成立的代数恒等式，并不用到市场出清。
- 实证：我在**非均衡**的 ŵ = (1,1,1) 与 (1.3,0.7,1.1) 上计算，差仍为 2.2e-16，而此时出清残差高达 0.01 至 0.14（归一化后）。
- 含义：这个检验不检验求解器是否收敛，也不检验 Xp、`sales`、出清方程是否写对。对 `evaluate()` 里 `Xp` 的 bug 完全盲目。
- 它只检验 λ'、P̂、Ŵ 三个公式（含 d̂ 的 c 项）彼此一致，有保护 (1)(2)(6) 式的价值，但**不应被报告为 "ACR 解析检验通过 = 求解器验证"**。
- 想要真有意义的 ACR 检验，应验证 ACR 的总福利公式在均衡处成立：使用 ACR 的 ŵ 内生场景，把 `λ̂_jj` 取自**独立计算**（例如先给定 ŵ 不经 `evaluate`，直接从均衡的 Xp 算出 λ̂_jj），或在已知闭式解的对称两国情形下比对 ŵ。
- 附：检验用 `eps.mean()`，因两部门 ε 相同故无影响，但换成异质 ε 会错位。
