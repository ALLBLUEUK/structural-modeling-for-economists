# strucmod v0.3 新功能使用说明（研究生版）

> 本说明是《strucmod 使用说明》（v0.2，33 页）的补充，只讲 v0.3 新增的三件事：做异质主体研究、不用 GAMS 做 CGE 关税模拟、把结果和论文数字核对清楚。前提是你已经按主手册装好 Python 和一种 AI 编程助手，并跑通过新凯恩斯示范项目。

> 关于命令中的路径：以下命令都在你的研究项目根目录（含 `model/`、`output/` 的目录）中运行，`<插件目录>` 指 strucmod 插件所在的目录。若直接运行仓库自带的验收案例（`examples/<案例>/`），`<插件目录>` 为 `../..`；若运行结项材料中的案例（`工作流验收/<案例>/`），`<插件目录>` 为 `../../strucmod-v0.3`。

## 一、v0.3 解决了什么问题

| 以前（v0.2） | 现在（v0.3） |
|---|---|
| 异质主体模板的核心求解函数尚未实现（返回 `TODO`） | 可直接运行的 Aiyagari / Bewley 稳态求解器 |
| CGE 只有 GAMS 模板，没有授权就没法练 | 纯 Python 的 Armington 关税模型，不需要 GAMS，也不需要 GTAP 授权 |
| 复现靠手工重跑、肉眼对比 | 一条命令复制项目、重跑、逐个数字比对 |
| 论文中的数字与数据来源是否一致，没有检查手段 | 逐条核对论文数字与数据源，示范论文里查出两处错误 |

## 二、做一个异质主体研究

### 1. 和 AI 助手说什么

```
请按 strucmod 工作流开始一个异质主体研究项目：在 Aiyagari 模型中，借贷限额的松紧如何影响均衡利率和储蓄率？
```

AI 会先起草 `spec.md`，交给经济逻辑评审和数学评审。评审意见一定要自己读一遍。v0.3 验收时，两位评审在这个问题上一共提出了 10 条必改意见，例如“借贷下限在利率小于等于零时没有定义”“收入过程没写清楚怎么归一化”。建议逐条读懂这些意见，再看代码。

### 2. 参数表要写哪些

在 `model/02_calibrate/<模型名>/calibration.csv` 里至少写：`beta, mu, alpha, delta, rho, sigma, n_z, n_a, a_max, b`。每个参数都要写来源。

### 3. 运行

```bash
python model/03_solve/<模型名>/solve.py --scenario baseline          # 基准
python model/03_solve/<模型名>/solve.py --scenario b2 --set b=2      # 改一个参数做比较静态
python model/03_solve/<模型名>/solve.py --scenario limit --set sigma=0.001 --set r_hi_eps=1e-8 --set a_max=200   # 极限检验
```

### 4. 怎么判断结果能不能用

打开 `output/checkpoints/<模型名>_<情形>_ss.json`，看 `validated`。只有它是 `true` 才能写进论文。它同时检查：

- 资本市场出清、资源约束 C + δK = Y 的残差
- 家庭问题和财富分布是否真的收敛
- 资产网格上端有没有人（有人说明网格开小了）
- 在 30 个利率点上扫描，市场出清是否只发生一次
- 收入过程离散化的质量（方差误差小于 5%）

一定要做极限检验：把收入风险设得几乎为零，利率应该回到 1/β − 1。这种情形下家庭积累的资产更多，需要把资产网格上界 `a_max` 放大到 200，否则网格上端会有质量，检验无法通过。验收时正是这个检验暴露出模板里的一个问题（财富分布在这种情形下收敛极慢，旧代码没收敛也没报错），修好后才通过。

### 5. 可以追问 AI 的问题

```
为什么 Tauchen 方法在 ρ = 0.9 时会高估收入方差？换成 Rouwenhorst 后利率为什么变高了？
```

```
放宽借贷约束后财富 Gini 系数反而上升，这说明储蓄行为更不平等了吗？
```

## 三、不用 GAMS 做一个关税模拟

### 1. 准备数据

`data/calibration/<模型名>/trade_flows.csv`，四列：`exporter,importer,sector,value`（出厂价贸易流）。数据要登记到 `manifest.json`。如果是自己编的示意数据，必须在数据登记、spec、每张图表和报告里都写明“示意数据”，地区最好用 A、B、C 这样的中性标签，否则很容易被误读成真实结论。

### 2. 写情形

`model/02_calibrate/<模型名>/scenarios.csv`：`scenario,exporter,importer,sector,tariff_new`。例如“A 对来自 B 的制造业加征 10%”写成 `S1,B,A,MAN,0.10`（注意出口方在前、进口方在后）。

### 3. 运行

```bash
python model/03_solve/<模型名>/solve.py --purge --checks --scenario S1
python <插件目录>/scripts/check_walras.py output/checkpoints/<模型名>_S1.json --tol 1e-9
```

`--purge` 先把基期贸易赤字剔除（否则换个计价单位结果就会变）；`--checks` 跑 11 项数值检验，其中最重要的是“独立水平量求解器交叉核对”：用另一种写法重新解同一个模型，两种实现一致，可以为求解结果提供交叉验证，但不能排除二者共同的设定错误。

### 4. 需要注意的一点

验收时，spec 里原本写着一个先验判断：“对方报复后，两国福利都比单边加税时低”。评审指出这不是定理，结果也证明报复反而让报复方的福利回升。不要把自己的直觉写成验收标准，否则正确的代码会被当成错误。

## 四、把结果和论文数字核对清楚

### 1. 一键复现

在项目根目录放一个 `run_all.sh`，写好从头到尾的运行命令，然后：

```bash
python <插件目录>/scripts/replicate_compare.py --cmd "bash run_all.sh" \
    --compare output/tables/xxx.csv --compare output/checkpoints/xxx.json
```

它会把整个项目复制到临时目录重跑，逐个数字比对，生成复现报告。原项目不会被改动。

### 2. 论文数字核对

在项目根目录写 `claims.csv`，每行登记论文里的一个数字和它的来源：

```
claim_id,doc,text_value,source,locator,factor,abs,note
R04,paper/sections/05_results.tex,0.518,results/tables/irf.csv,row=0;col=real_rate_annualised_pp,1,0,实际利率
```

然后运行 `python <插件目录>/scripts/check_claims.py claims.csv`。v0.2 示范论文第一次跑就查出两处错误：一处是 0.518 写成了 0.522，另一处是先把 0.04448 四舍五入成 0.044 再乘以 4，得到 0.176，而正确值是 0.178。交论文、交开题报告之前都应该跑一遍。

## 五、验收案例在哪里

三个完整的验收案例（含全部评审意见、失败记录、复现报告和分析报告）在仓库的 `examples/` 目录下：

- `case_ha_aiyagari_borrowing/`：异质主体，借贷约束与均衡利率
- `case_cge_armington_tariff/`：CGE，单边关税与对等报复（示意数据）
- `case_nk_replicate/`：对 v0.2 示范论文的复现核对与勘误

建议先读每个案例 `logs/sessions/` 下的运行记录，再对照 `quality_reports/` 里的评审意见，看工作流在每一步是怎么发现问题、怎么修正的。
